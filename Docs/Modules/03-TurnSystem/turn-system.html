03. 回合制状态机与队伍流转 (Turn & Team Flow)

Flash AS2 原版回合生命周期、Inactivity 连击静止结算门限与胜负仲裁

1. 回合状态机 (TurnPhase Lifecycle)

《Mutiny》作为经典回合制战术游戏，回合的流转不能仅凭定时器，而必须精确跟踪所有物体的运动与连锁结算生命周期。 MutinyTurnManager 管理整场对局的核心状态迁移：

[NotStarted] → StartGame() → [TurnActive] (玩家瞄准 / AI思考)
↓ 释放武器 / CommitAction
[ActionExecuting] (抛掷物飞行 / 爆炸波及 / 角色击退)
↓ 所有物体达到 Rest 条件
[Settling] (InactivityTicks 累加 > 10 tick / 0.4s)
↓
队伍存活判定 ? → 胜负已定 → [GameOver] (胜利/失败/平局)
↓ 均存活
切换队伍 → [TurnActive] (补充保底弹药、重置资格)
状态 (TurnPhase) 触发条件 系统行为与权限控制
NotStarted 关卡构建未完成或队伍为空 禁用一切玩家输入与物理计时器。
TurnActive 新回合开始或上一回合结算完毕 允许玩家点击选人、1~9 切换武器、拖拽蓄力拉线；或唤醒 AI 展开决策。
ActionExecuting 武器脱手 (Fire/Twang) 或点击 Pass 锁定输入，弹道预测线隐藏，镜头平滑切向弹道焦点，物理步进全速模拟。
Settling 场上所有刚体与特效暂时停稳 启动 Inactivity 计数器，等待连续 10 个 tick 稳定期，防止跳帧提前结算。
GameOver 任意一方队伍存活数归零 (AliveCount == 0) 停止物理结算，播放对应音效，调用持久化解锁下一关，弹窗显示结算面板。

2. 核心算法：全场静止门限 (Inactivity Settling)

在回合制抛掷游戏中，最棘手的 Bug 是“炮弹还在空中爆炸，或者角色还在空中下落，回合就被提前切走了”。 原版 Flash AS2 采用了严谨的 inactivity > 10 计数器算法，本项目 1:1 予以复刻：

Inactivity Settling 准则： 只有当场上无一物体处于运动态、无一武器在飞行、无一爆炸尚未播放完毕、无一角色在扣血结算时，静止计数器才会累加。 必须在 连续 10 个物理 tick（0.4 秒） 内全场保持完全绝对静止，系统才判定当前行动彻底结束。 若在第 9 个 tick 发生了连锁爆炸或角色受击滑动，计数器立即被归零重置！

静止阻挡检测器 (CheckAllBodiesAtRest)

private bool CheckAllBodiesAtRest(out string blocker)
{
    // 1. 检查所有海盗角色：必须存活且物理刚体 IsAtRest，且扣血滚动动画已完成
    for (int i = 0; i < m_AllCharacters.Count; i++)
    {
        var ch = m_AllCharacters[i];
        if (ch == null) continue;

        if (ch.IsResolvingHealthDisplay)
        {
            blocker = $"character:{ch.name} resolving_health";
            return false;
        }
        if (ch.IsAlive && ch.PhysicsBody != null && !ch.PhysicsBody.IsAtRest)
        {
            blocker = $"character:{ch.name} moving";
            return false;
        }
    }

    // 2. 检查场上是否仍有已发射但未结束的武器 (如滚动的炸药、飞行的香蕉)
    var activeWeapons = FindObjectsByType<MutinyWeapon>();
    for (int i = 0; i < activeWeapons.Length; i++)
    {
        var w = activeWeapons[i];
        if (w != null && w.IsFired && !w.IsFinished)
        {
            blocker = $"weapon:{w.WeaponType}";
            return false;
        }
    }

    // 3. 检查是否仍有未播放完毕的爆炸特效 (MutinyExplosion)
    if (FindObjectsByType<MutinyExplosion>().Length > 0)
    {
        blocker = "explosions_active";
        return false;
    }

    blocker = null;
    return true;
}

3. 队伍轮换、先手规则与保底弹药

队伍先手仲裁 (First Turn)

  • 单人剧情模式：敌方为 AI 控制（Team2.IsAiControlled == true），永远由红队（玩家）率先行动。
  • 本地双人模式：双方均为人类，开局以 50% 随机概率决定谁先手。
  • 队长聚焦：开局时镜头默认平滑对准队伍队长（Captain/Chief），但不强制锁定选中。

回合重置与原版保底弹药规则

当队伍开启新回合 (Team.StartTurn) 时：

  • 行动资格刷新：所有存活角色的 CanThrow = true; CanShoot = true; 恢复。
  • 原版特有“空手赠弹”规则：如果某个海盗在战斗中耗尽了所有战术武器，系统会在回合开始时自动为其赠送 1 发基础加农炮弹 (cannonball)，防止死锁卡关。
  • 空投宝箱：调用 MutinyTreasureChestManager.TryDropNew() 计算概率掉落空投补给。

队伍交替执行逻辑

if (CurrentTeam != null && CurrentTeam.IsTurnComplete())
{
    OnTurnEnded?.Invoke(CurrentTeam);
    CurrentTeam.FinishTurn();

    // 红蓝交替：T1 -> T2 -> T1
    CurrentTeam = (CurrentTeam == Team1) ? Team2 : Team1;
    TurnCount++;
    CurrentPhase = TurnPhase.TurnActive;
    m_ActionCommittedThisTurn = false;

    // 开启新队伍回合
    CurrentTeam.StartTurn();
    OnTurnStarted?.Invoke(CurrentTeam);
}

4. 胜负判定与存档自动化绑定

在每次静止门限通过后，系统优先判定游戏胜负结果 (GameOverResult)：

判定分支 胜负结论 视听与业务系统联动
team1Defeated && team2Defeated 平局 (Draw) 播放 die 音效，弹出结算面板，不解锁后续关卡。
team2Defeated 玩家胜利 (Team1Wins) 播放 ching 胜利音效，自动解锁下一关关卡索引 (UnlockLevel(currentIndex + 1))。
team1Defeated 敌方胜利 (Team2Wins) 播放 fan 嘲讽音效，弹出失败与重试界面。
