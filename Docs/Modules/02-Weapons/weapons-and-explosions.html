2. 生产路径：从选武器到回合结算

ActionMenu → SelectWeapon → SpawnWeapon → Initialize + PrepareForEquip → WeaponReady → Aiming → Commit → ActionExecuting → Finish / 特殊阶段

共同入口

  • MutinyWeaponFactory 按武器 ID 创建真实实例，再调用 Initialize(owner) 与 PrepareForEquip()。
  • 常规装备点为角色 (x, y-10px)；Boulder 是原版例外，位于 (x, y-30px)。
  • 常规抛射由 Twang 计算速度并提交；Cannon、Anchor、Wooden Crate、Gunpowder Barrel、Seagull、Tidal Wave 和 Voodoo Doll 有专用输入路径。

待抛射与取消

  • 选择武器后先显示真实实例，未提交前不扣库存。
  • 角色下方取消叉号销毁未发射实例并回到武器菜单。
  • 用户授权扩展：仅在 Aiming 中右键会取消本次拉力，返回 WeaponReady，不会退回武器菜单或扣库存。

坐标使用 Flash 像素；MutinyPhysics.PixelsPerUnit = 32，模拟 tick 为 1 / 25s。所有显示资源须和这套坐标系匹配，不能默认采用 Unity 的 100 PPU。

4. 统一爆炸：当前生产实现

MutinyExplosion.Spawn 以 Flash 像素坐标创建对象，按 size / 100 缩放爆炸图像，在 25 Hz 的第 3 帧执行一次伤害。当前代码实现的径向公式如下：

radius = size * 0.5f + 20f
ratio  = 1f - distance / radius
force  = 0.06f * ratio * maxDamage

velocityX += normX * 5f * force
velocityY += normY * 5f * force - force * 6f
damage     = maxDamage * ratio

当前覆盖

  • 存活角色的距离衰减伤害、上抛冲量和施放者 evilness。
  • 木箱与火药桶的非对称 AABB 最近点判定及连锁入口。
  • 8 帧爆炸资源、排序层和第 3 帧伤害调用。

仍须验收

  • 每种武器是否应在创建时、命中时或爆炸伤害帧播放 pop。
  • 爆炸动画的像素缩放、重叠层级、镜头震动与所有对象分支。
  • 固定场景下的原版逐 tick 数值、画面和音频并发。

5. Boulder：最新视觉复刻修正

原版 DefineSprite_872_boulder 不是一张普通静态图片：depth 1 的 rotating 子层随 velocityX * 2.5 旋转，depth 3 的 overlay 保持不转。两个子层均以 Boulder 根注册点为中心，都是 64 × 64 px，时间轴矩阵为单位缩放、零位移。

人工验证顺序

  1. 从行动菜单选择武器，确认 WeaponReady 的真实装备实例、取消叉号和库存时机。
  2. 按该武器的规格重放玩家与 AI 路径，记录 25 Hz tick、位置、速度、阶段、库存、音频和结束原因。
  3. 对照原版相同输入，先定位第一个分歧 tick，再检查视觉、声音、镜头和回合结算。
