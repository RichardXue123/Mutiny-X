01. 离散物理与碰撞模块 (Discrete Physics)

1:1 逆向 Flash 原版 25 Hz 确定性物理积分、AABB 栅格碰撞与水域动力学

1. 核心设计背景：为何抛弃 Unity 物理引擎？

在《Mutiny》中，弹弓瞄准的手感、炮弹反弹轨迹以及炸药静止判定的手感是游戏的核心体验。Flash 原版基于 ActionScript 2 (AVM1)，在每帧（25 FPS）以极其固定的离散公式更新像素坐标：

确定性要求： 原版所有的物理运动、初速度衰减、弹道虚线预测与入水浮力，均建立在离散像素步长之上。如果直接套用 Unity 的 Rigidbody2D（PhysX/Box2D 连续时间求解器），会因为浮点累积误差、平滑插值以及材质摩擦力模型不一致，导致弹道预测线与真实飞行轨迹无法做到 100% 绝对重合，且破坏原版的“蓄力-反弹”物理原汁原味性。
对比维度 Unity 内置 Rigidbody2D Mutiny X 自研离散物理 (MutinyPhysics)
步长机制 基于 FixedUpdate (默认 50 Hz) 连续积分 固定 25 Hz (TimeStep = 0.04s)，单 tick 步进
坐标单位 Unity 世界米 (Units) Flash 像素 (Pixel Coordinates)，渲染时转 Units
确定性预测 难以快速无副作用预测 60 步后的落点 纯状态快照数学求解，可在 1 毫秒内计算出 60 步轨迹
碰撞检测 连续重叠检测 (Circle / BoxCollider2D) 逐轴 Swept AABB 栅格扫描 (完全重现原版 Flash Solid.as)

2. 坐标系映射与核心物理常数

游戏内部所有物理积分均在 Flash 像素空间 中完成，只有在挂载物同步渲染时，才映射到 Unity 世界坐标：

坐标系转换关系

  • 网格比例：PixelsPerUnit = 32f (1 个瓦片 Tile = 32 × 32 像素)。
  • 原点约定：Flash 原点位于左上角（+X 向右，+Y 向下）；Unity 原点 Y 轴向上。
  • 转换公式：
    Unity.X = Flash.X / 32.0f
    Unity.Y = -Flash.Y / 32.0f

常量标识 数值 物理含义

弹弓拉拽蓄力初速度计算 (Twang Velocity)

Vector2 CalculateTwangVelocity(Vector2 startPosPx, Vector2 dragPosPx, float maxForce = 20.0f)
{
    // 反向拉拽矢量，缩放系数为 -0.25
    float vx = (dragPosPx.x - startPosPx.x) * -0.25f;
    float vy = (dragPosPx.y - startPosPx.y) * -0.25f;

    float sqrLen = vx * vx + vy * vy;
    if (sqrLen > maxForce * maxForce)
    {
        float len = Mathf.Sqrt(sqrLen);
        vx *= maxForce / len;
        vy *= maxForce / len;
    }
    return new Vector2(vx, vy);
}

3. 物理状态结构体与两步碰撞算法

物理引擎的核心执行函数为纯静态、无 GC 分配的 MutinyPhysics.Step(ref PhysicsBodyState body, string[,] terrainGrid, int w, int h)。

数据结构：PhysicsBodyState

public struct PhysicsBodyState
{
    public float X, Y;                   // Flash 像素坐标 (浮点数)
    public float VelocityX, VelocityY;   // 当前速度分量 (px/tick)
    public float Weight;                 // 重力系数 (默认 1.0f)
    public float Bounce;                 // 地面弹性系数 (默认 0.2f)
    public float Friction;               // 地面摩擦力 (道具 0.3f，海盗角色 2.0f)
    public float LeftExtent, RightExtent; // AABB 包围盒半径 (左/右，默认 6px)
    public float TopExtent, BottomExtent; // AABB 包围盒半径 (上/下，默认 8px)
    public bool HitsTiles;               // 是否与地形发生碰撞

    // 静止阈值：水平几乎归零且垂直动能小于 0.2 px/tick
    public bool IsAtRest => Mathf.Abs(VelocityX) < 0.001f && Mathf.Abs(VelocityY) < 0.2f;
}

两步碰撞求解 (Two-Pass Swept Collision)

原版 Flash Solid.as 采用先垂直、后水平的独立轴求解策略，有效规避了角落斜向穿透与卡墙死锁问题：

  1. 垂直步进与碰撞：
    • 累加重力：body.VelocityY += body.Weight;
    • 计算 Y 轴跨越的格网范围 minGridRow ~ maxGridRow。
    • 沿运动方向逐行探测格子是否为实体 IsSolidTile（排除空标记 "-" 与水面涟漪 "ripple"）。
    • 若发生碰撞：修正 Y 轴坐标贴合瓦片边缘（保留 0.1px 偏移），垂直反弹 VelocityY *= -Bounce。
    • 地面动摩擦衰减：若是触地反弹，水平速度立即扣减滑动摩擦力：absVx = Math.Max(0, absVx - Friction)。
  2. 水平步进与碰撞：
    • 计算 X 轴跨越的格网范围 minGridCol ~ maxGridCol。
    • 沿运动方向逐列扫描是否存在阻挡实体。
    • 若撞墙：修正 X 轴贴合墙壁边缘，固定反弹 VelocityX *= -0.4f。
  3. 静止判定： 检查 IsAtRest 状态并填充 StepResult。

4. Unity 运行时宿主组件：MutinyPhysicsBody

为了将纯数学的 MutinyPhysics 接入 Unity 生命周期，实现了 MutinyPhysicsBody（MonoBehaviour）。它采用累加器固定步长模式，完全隔离了渲染帧率对物理结算的影响。

时间累加器与 Substep 保护

private void Update()
{
    if (!IsActive) return;

    // 累加渲染耗时
    m_TimeAccumulator += Time.deltaTime;
    int maxSubSteps = 5; // 限制单帧最大步数，防止极端卡顿下的死循环
    int steps = 0;

    while (m_TimeAccumulator >= MutinyPhysics.TimeStep && steps < maxSubSteps)
    {
        m_TimeAccumulator -= MutinyPhysics.TimeStep;
        steps++;

        // 执行一次离散物理求解
        StepResult res = MutinyPhysics.Step(ref State, m_CachedTerrain, m_GridWidth, m_GridHeight);

        // 检查落水动力学
        EvaluateWaterState();

        // 触发对应的状态机事件
        if (res.HitFloor) OnFloorLanded?.Invoke();
        if (res.HitLeftWall || res.HitRightWall) OnWallHit?.Invoke();
        if (res.IsAtRest) OnRest?.Invoke();
        OnSimulationStep?.Invoke();
    }

    // 将最终离散位置映射同步到 Unity Transform
    if (SyncTransform)
    {
        transform.position = MutinyPhysics.PixelToUnity(State.X, State.Y);
    }
}

落水动力学 (Water Mechanics)

当实体的 State.Y > WaterPixelY 时触发落水，原版定义了独特的入水阻尼与限速阻抗：

  • 速度阻尼：VelocityX *= 0.8f; VelocityY *= 0.8f;
  • 浮力与下沉限速：若 VelocityY > 1.5f，每 tick 扣除 4.0f 并将下沉速度截断在最低 1.5f。
  • 入水旋转翻滚：角速度与动量成正比 transform.Rotate(0, 0, -(vx + vy) * 4f)。

5. 确定性弹道预测 (Deterministic Trajectory)

在玩家拖拽瞄准（或 AI 决策评估）时，调用 MutinyPhysics.SimulateTrajectory：

通过在内存中拷贝一个临时的 PhysicsBodyState simBody = initialState 副本，连续调用 Step 模拟最多 60 步，记录经过的每一个像素坐标并转换为 Unity 坐标点。 由于算法中没有任何不确定的浮点随机数或外部物理引擎干扰，弹道虚线预测点就是物体最终实际飞行的绝对轨迹。
