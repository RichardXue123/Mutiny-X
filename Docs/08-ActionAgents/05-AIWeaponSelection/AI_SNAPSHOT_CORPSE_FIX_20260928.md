# AI 搜索被下沉尸体反复取消（2026-09-28）

修复前建立的规格，现补充实际结果。用户在第 12 关反馈 Luck=9999/1000 都出现 `board changed → watchdog → thinking` 循环。修复分帧搜索引入的回归，不减少采样、不改变世界物理或评分。

## 证据与原因

- 用户截图及当前 `Logs/Editor.log`：第 12 关 9999 场景先有 `Char_04_skeletonPirate_T2` 落水，之后 T2 开始无限重算；1000 场景先有 `Char_15_redPirateCaptain_T1` 落水，之后再次重算。
- Unity：`MutinyPhysicsBody.AdvanceSimulationTick/EvaluateWaterState` 继续推进尸体；`MutinyCharacter.Drown` 将角色标记死亡但不停止物理。回合管理器的落稳检查跳过死亡角色。
- 缺陷：`DecisionSnapshot.Matches` 却对全部角色（包括死亡角色）精确比较位置/速度；尸体持续下沉导致每个物理 tick 废弃搜索，watchdog 重启，从而不能完成较长的高 Luck 搜索。小 Luck 不一定能跨过物理 tick，因此之前简单活角色场景没有覆盖。
- 原版：`Character.as::advance` 死后仍运动/水中阻尼；`aiThink` 跳过死亡角色的行动，但敌方中心计算保留队伍中死亡角色位置；`Team.as::advance` 分帧推进已有候选，没有此全棋盘相等重启门。

## 边界

只忽略“快照已死，当前仍死”的物理运动。生命/死亡状态变化必须重算，活角色仍精确校验。尸体的位置固定于本次搜索快照，不会持续刷新参与已评分候选；新决策读取新位置。浮点容差不是本次修复方案。

## 完成口径

- 静态确认：循环由对下沉尸体的精确物理比较引起；原版仍推进尸体，且死亡条目没有从敌方中心计算中删除。
- 已实现：只忽略已死且仍死的被动物理漂移；存活状态转换仍重算，原评分名单/固定快照/随机/采样不变。失效日志增加原因，物理差异只输出变化字段。
- 实际测试通过：上列 54/54 + 209/209，含原生 Level 12 全库存与真实提交，不只测试局部布尔值。
- 待运行验证：用户主工程有摄像机的可视对局、Android 真机、更多死亡/宝箱/箱体组合、其他关卡长期测试。
- 已知差异：尸体位置按本次决策快照冻结，世界中的尸体不冻结；这是既有授权快照扩展的修复，不宣称原版边运动边 `aiThink` 的取值时刻与 Unity 相同。极高 Luck 总等待时间仍存在，默认 3 ms 为软预算；本次未调整镜头、帧率插值或物理。
