# 手柄验证（2026-09-26）

对应 [GP-NAV-01 至 GP-SCOPE-01](../../08-ActionAgents/02-PlayerInput/CONTROLLER_SUPPORT.md)、[GP-SPC-01 至 GP-SPC-06](../../08-ActionAgents/02-PlayerInput/CONTROLLER_SPECIAL_WEAPONS.md)、[GP-POWER-01/02、GP-SPC-07](../../08-ActionAgents/02-PlayerInput/CONTROLLER_TRIGGER_POWER.md)及 [GP-CAN-01 至 GP-CAN-05](../../08-ActionAgents/02-PlayerInput/CONTROLLER_CANNON.md)。这是用户授权扩展，原版鼠标行为仍为独立基线。

## 静态确认

- 项目现有 Unity 6000.6.0f1 / Input System 1.20 已支持 `Gamepad` 动作；新输入资源不替换原触摸/鼠标入口。
- 原 `Solid.as::twang/drawTwangLine` 的反向拖动、0.25 换算、20/30 最大力与现有最小拖动资格由原生产方法执行。用户本次纠正手柄左杆应表示**向后拉**的方向；它对应拖动端点，初速方向相反。
- 原按钮回调、取消资格、库存、行动提交和相机边界复用。IMGUI 控件按实际绘制注册，不以模拟鼠标事件完成导航。
- 原 `Cannon.as` 拉环范围 -21 至 -40、固定 30 力炮弹、回弹再开炮、部署圆和独立炮弹为静态确认。手柄 A 在任意视觉力度提交是本轮用户授权扩展，鼠标有效释放门仍 `<-30`。
- 原 `Team.as::startTurn:273-280` 只设置镜头角色（首次队伍回合优先队长），并不隐式选人。GP-CHAR-02 自动角色焦点是本轮用户授权扩展，A 仍沿同一生产选人入口确认。
- GP-NAV-02 缺陷静态定位：`CaptureInput` 在前端 UI 路由前调用角色焦点准备，而该准备仅检查回合/角色状态，没有限定当前页面；后台保留战斗对象时会重写主菜单指针。此前 294 条回归分别测试前端与战斗，未覆盖两者并存。

## 已实现

- 新分支 `feature/controller_support`；十字键焦点/选人/选武器、双摇杆、LT/RT、A/B、Start。
- 普通跳跃和普通投掷；力度条、百分比、共享悬停状态和软件指针。
- LT/RT 任一扳机进入瞄准，LT 减力、RT 增力，以有效按压深度控制变化速度。累计力度限制 0–100%，松开保持，满压默认每秒改变 50 个百分点。A 在松开扳机后仍通过共享入口发射。
- 页面/弹窗输入路由、同帧取消优先、按住 A 不跨页连点、弹窗请求后立即拦截底层控件。
- 鼠标/触摸蓄力与手柄蓄力互不抢占；键盘/鼠标/触摸恢复原入口；断连/失焦取消、重连回中保护。
- 锚、海鸥、海啸、木箱、火药桶、巫毒、香蕉、降落伞炸弹、金币的手柄操作；原版特殊光标与可放置叉随左摇杆软件指针移动。
- 大炮开放手柄选择：待命左杆部署，LT/RT 进入瞄准后左杆后拉调炮口，扳机只改拉环长度，A 固定 30 力提交；B 保留部署位置返回待命。装填回弹期间阻止回合结算，原鼠标/触摸装备与拉栓门保留。
- 手柄玩家回合自动聚焦镜头的回合角色；目标在镜头抵达后保留，首个 A 即打开行动菜单。焦点在 UI 路由前建立，十字键可改选、左杆主动移动可退出焦点；鼠标切换、AI/死亡目标和新回合会清理旧焦点。
- 角色自动聚焦限定于 `board` 上下文，前端页面、行动菜单与弹窗由其原 UI 路由持有指针。

## 实际测试

运行于复制的隔离工程 `_codex_controller_verify_20260926`，使用 Unity 6000.6.0f1 图形模式 Play Mode、空场景与实际 Game View。测试期间没有切换主工程的 Play Mode 或场景。

`MutinyControllerVerification` 将 `GamepadState`、`MouseState`、`KeyboardState` 入队至真实 Input System；前端和战斗面板经真实 Update/OnGUI 按钮回调执行。战斗夹具以 `Turn.Initialize` 建立回合，并通过生产选人、选武器、瞄准、Twang 和提交入口检查库存/回合阶段。GUI 夹具只暂停模拟推进，输入与界面动画继续运行。

- 前端 Help、Play、单人选关和 B 返回；长按 A 穿过多个 OnGUI 和过渡只执行一次。
- 真实行动面板的角色确认、普通武器槽、待命返回、Start 弹窗、Continue 与 Cancel Character。
- 弹窗淡入前的输入所有权、淡入时 B 不操作底层控件；瞄准 A 不被角落按钮抢占。
- 双扳机松开保持力度且不提交；20/30 最大力和半力实际发射；左杆回中与移动相机保留方向；零力不提交。
- 本次新增方向回归：左下拉经实际 Twang 向右上发射，右拉使 Rum Bottle 向左飞、左拉使半力 Rum Bottle 向右飞，上拉使 Cherry Bomb 向下飞，下拉使角色向上跳。未拉动左杆时 RT+A 不发射、不扣库存，回待命后松开 RT 才能再次蓄力。
- A/B 同帧取消、取消后任一扳机持续按住不重新蓄力、提交后不能回滚；真实库存只扣一次。
- 断连/失焦取消；重连按住键需先回中；鼠标和手柄进行中的蓄力互不抢占；键盘按下恢复原路径。
- 复跑原有角色蓄力/鼠标触摸取消、滚屏箭头、相机显示位置与跟随专项。
- 实际虚拟 Gamepad 驱动锚图标跟随、锚横坐标与固定高度、海鸥高度与飞行中单次投弹、海啸固定起点、木箱三次/火药桶两次放置及非法叉、巫毒目标绑定后投掷、香蕉追加引爆、降落伞松开后重新按住 A 扇风、金币连续第二枚。木箱/火药桶用例检出并修复了 `ActionExecuting` 中取当前角色被拒的问题；降落伞用例检出了发射时 A 误作为扇风，以及飞行时 A 落入普通选人状态机的问题。

## 已知差异与范围

- 大炮手柄 A 在任意视觉拉环长度均能提交；原版鼠标必须有效拉栓释放。此差异为用户明确授权，不登记为原版一致性。
- 自动聚焦镜头角色仅用于手柄选人；聚焦不设置 `SelectedCharacter`，A 才正式选人。它是用户授权扩展，不登记为原版隐式选人规则。
- 当前按标准 `Gamepad` 的南侧/东侧按钮绑定 A/B；未增加自定义改键、传统 `Joystick` 设备布局和振动。
- Credits 外链仍沿用原鼠标交互；该页面的 Back 可由 B 操作。
- 行动面板、对话、AI 或自动跟随期间右杆不抢镜头；普通待命和手柄瞄准期间允许平移。

## 复跑入口

在隔离工程打开空场景，执行 `Mutiny/Controller/Validate Initial Support Play Mode`。菜单在非空场景或已经运行 Play Mode 时拒绝创建夹具，以免干扰实际关卡。

自动执行入口为 `Mutiny.Verification.Editor.MutinyControllerVerificationMenu.RunBatch`，必须使用独立工程、图形模式和 Game View；纯 `-batchmode` 不作为 IMGUI 实际交互验收。输出根目录 `controller-verification.txt` 与 `controller-ui.png`。
