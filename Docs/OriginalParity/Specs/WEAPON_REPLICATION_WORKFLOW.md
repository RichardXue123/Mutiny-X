# 武器复刻工作流与交付门槛

本流程适用于“复刻某个武器”“修复某个武器”及“复刻下一个武器”。它是 `WEAPON_REPLICATION_PLAN.md` 的强制执行流程；后者记录每种武器的范围和进度，本文件规定如何得到可验证的结论。

## WPN-PROC-01：先定义交付物，再开始实现

“有一个能发射的 C# 类”“能在场景中看到 Sprite”或“C# 编译通过”都只是**静态初版实现**，不得称为“已实现”或“已完成”。一次武器复刻必须交付：

1. 本武器的原版来源图、规则表和待确认项；
2. 从菜单/AI 到回合结算的状态机与 25 Hz 时序；
3. 图像、子时间轴、显示层、注册点和音效的映射；
4. 经生产入口驱动的回归用例及其实际结果；
5. 原版与 Unity 的运行对照记录，或明确标出尚未运行。

若只具备第 1–3 项和代码初版，状态只能是“实现中（静态初版）”。不得把用户尚未执行的 Unity Play Mode 或原版运行对照写成通过。

## WPN-PROC-02：建立原版来源图，禁止只翻译单个武器类

每个武器规格首先建立下表。原版期望只能来自 AS2、pcode、SWF 时间轴/资源或原版运行记录；现有 C#、旧 TODO 和 AI 总结不能作为原版证据。

| 层 | 必查原版节点 | 必记内容 | Unity 对应入口 |
|---|---|---|---|
| 武器本体 | 武器类、父类、全部 override | 字段默认值、分支、是否调用父方法 | 工厂、具体武器类 |
| 调用者 | 玩家输入、行动菜单、角色、背包 | 选中、装备、按下、持续、释放、取消、扣库存 | 输入状态机、菜单、背包 |
| AI | `aiSimulation`、`aiPerform` 及调用者 | 选点、随机次数、等待 tick、AI 专用发射/放置路径 | AI 决策与执行 |
| 物理与世界 | `Solid`、`Weapon`、`Character`、`TileSystem`、水/地图边界 | 接触顺序、角色/箱/地形/水/边界分支、结束条件 | 物理、碰撞、回合结算 |
| 表现 | linkage、DefineSprite、父/子时间轴、深度 | 帧标签、帧脚本、注册点、遮罩、混色、创建深度 | Prefab、动画、排序层 |
| 声音 | `playSound`、帧声音、资源索引 | 声音名、触发帧/tick、并发、循环/停止、随机 | 音频事件 |
| 回合与镜头 | Controller、Team、Camera 相关调用 | 行动消耗、锁定、镜头目标、inactivity、跨回合存续 | TurnManager、Camera |

每行至少写出“原版路径/符号或运行记录 → 规则 ID → Unity 方法 → 用例 ID → 证据状态”。未能解析的节点标为待确认，不能用父类默认值或相邻武器的行为填补。

## WPN-PROC-03：按调用路径列状态转换

武器不是单一路径。至少分别列出下列入口；不存在时也要用原版证据标记“不存在”。

| 路径 | 前置状态 | 输入/触发 | 原版调用链 | 后置状态与可观察结果 |
|---|---|---|---|---|
| 玩家选中/待抛射 | 菜单、库存、行动资格 | 点击图标 | 菜单 → 角色/武器 | 手持实例、取消标记、UI/镜头 |
| 玩家瞄准与提交 | 待抛射 | 左键按下、保持、释放 | 输入 → 具体方法/父方法 | 拉力、预测、扣库存、发射/放置 |
| 取消与非法输入 | 待抛射/瞄准 | 叉号、右键、非法位置 | 具体分支 | 保留或销毁什么、是否扣库存 |
| AI | AI 回合 | 模拟、选点、执行 | AI → `aiPerform`/专用分支 | 随机、等待、实际提交 |
| 运行中 | 已提交 | 每个 25 Hz tick、接触、帧事件 | `advance`/`contact`/时间轴 | 物理、子对象、伤害、声音 |
| 收尾 | 活动/特殊阶段 | 静止、爆炸、出界、入水、子对象结束 | `finish`/父类/Controller | 锁定、inactivity、回合是否可结束 |

状态至少区分：`Selected`、`Ready`（待抛射）、`Aiming/Placing`、`Committed`、`Active`、武器专有特殊阶段、`Resolving`、`Finished`。多发、可部署、可遥控或会生成子对象的武器还要为每个子对象写生命周期。禁止用一个 `fired` 布尔值合并这些可观察状态。

## WPN-PROC-04：逐路径核对继承、阈值和 25 Hz 顺序

1. 对每个路径写明调用的是具体 override、父类实现，还是完全绕过父类。不能因为方法名相同就复用通用发射、伤害或结束逻辑。
2. 所有比较符号和值都入表：`<`、`<=`、`>`、`>=`、整数化、随机样本数、tick 延迟和边界坐标都属于规则。
3. 记录原版每个 25 Hz tick 的顺序：输入、速度更新、接触回调、帧脚本、声音、状态计时、对象销毁和回合检查。Unity 物理回调必须被适配到这一顺序，而不是由引擎回调的到达顺序决定行为。
4. 预测线、AI 模拟和实际执行各自使用原版对应路径；只有原版明确共享参数时才能共用实现。

这一步专门防止两类已出现的错误：Boulder 的可达玩家/AI 路径不应套用另一路径的 release 系数；Cannonball 的开火不应被通用抛射力上限截断。它们是审计提醒，不是可推广到其他武器的默认规则。

## WPN-PROC-05：把表现拆成可独立验证的显示契约

静态导出的单张 PNG 不能证明原版的时间轴行为。每种武器建立表现表，至少包含：

| 阶段/帧 | 原版 linkage、帧或子对象 | 位置/注册点/父节点 | 朝向、缩放、旋转 | 深度、排序、遮罩/混色 | 创建与销毁时机 |
|---|---|---|---|---|---|

必须逐项覆盖手持、瞄准、释放、飞行/滚动、碰撞、引信/特殊阶段、伤害/爆炸、淡出、残骸和子对象。对象释放后从角色层转到场景层、父/子旋转分离、后创建对象覆盖前对象、白化/透明、以及帧事件驱动的子对象都必须单独记录。

若原版有动态子元素，不能把整张面板或整件武器的合成图当作全部状态；应保留子层或提供能表达同样独立状态的组合。出现闪烁时，先核对原版 Flash depth 与 Unity sorting order/透明排序，再调整美术位置。

## WPN-PROC-06：声音只从原版事件映射，不从“手感”补全

建立下表，包含“没有声音”的结论：

| 规则 ID | 原版事件/帧 | 音频名或资源 | 条件与节流 | Unity 调用点 | 用例 |
|---|---|---|---|---|---|

发射、碰撞、滚动、反弹、入水、引信、爆炸、特殊阶段和收尾应逐项查证。一个碰撞音只有在原版的对应物理回调和 tick 条件满足时才播放；不要因“角色被击中”或“物体正在移动”就添加声效。静态代码找不到独立声音时，记录为“静态未发现，待运行对照”，不得擅自复用另一武器或角色的声音链。

## WPN-PROC-07：实现时保持可追溯和可调试

- 每条 Unity 分支可回溯到规则 ID；公用 helper 只有在**具体原版调用路径**也相同的前提下才能复用。否则建立具名 override/adapter，并在规格中说明差异。
- 在关键边界打印结构化日志：武器 ID、规则 ID、tick、拥有者、阶段、输入/接触类型、关键参数、库存、子对象数及结束原因。日志必须来自生产路径，不能只在测试替身中出现。
- 不为使当前实现通过而改写原版规格。发现差异即按 `REPLICATION_STANDARD.md` 的缺陷卡格式登记，并新增能重现该差异的生产入口用例。

## WPN-PROC-08：验证分层，且用例必须能区分错误实现

每种武器至少具备以下验收层：

1. **规则/模拟**：由生产工厂、生产输入或生产 AI 入口驱动；逐 tick 断言状态、位置/速度、伤害、库存、对象存续、动画事件、排序和音频事件。
2. **生产场景**：从行动菜单实际选中，验证待抛射、瞄准、释放/放置、取消、AI、回合结算和 UI/镜头。
3. **原版对照**：相同关卡、角色位置、瞄准向量、随机种子（可得时）和输入序列下，保存逐 tick 日志、关键帧及音频事件对照。

每个缺陷都要新增一个会在修复前失败、修复后通过的用例。用例至少覆盖正常路径、临界阈值两侧、地面/墙/顶/角色/箱子/水/出界、零库存、取消、跨回合残留，以及该武器的专有子对象或多阶段输入。直接改私有布尔值、重写公式或调用测试专用入口不算生产验证。

## WPN-PROC-09：进度记录与交付报告

每次修改在该武器规格及 `WEAPON_REPLICATION_PLAN.md` 中分别更新以下事实，不得合并成笼统的“已复刻”：

| 项目 | 记录内容 |
|---|---|
| 静态确认 | 已核对的原版文件、pcode、时间轴、资源和规则 ID |
| 已实现 | Unity 入口、状态/显示/音频映射及新日志 |
| 自动测试通过 | 实际运行的测试名、生产入口和结果 |
| 待运行验证 | 未执行的 Unity Play Mode、原版对照及其原因 |
| 已知差异/待确认 | 证据缺口、观察冲突、影响范围和下一步 |

编译成功只记为“代码检查通过”，不能填入“自动测试通过”或“原版对照通过”。发现用户复现的问题后，先记录最早可观察分歧、对应原版路径与 Unity 路径，再修复；修复说明必须链接回该缺陷用例。

## WPN-PROC-10：每次开始和结束时的清单

### 开始实现前

- [ ] 已建立本武器的来源图，包含父类、调用者、AI、物理、时间轴/资源、音频和回合。
- [ ] 已列出玩家、AI、取消、运行与收尾的状态转换；未知项已标注。
- [ ] 已建立数值/阈值/25 Hz 顺序表、显示契约和声音映射。
- [ ] 已定义从生产入口执行的边界用例及原版对照场景。

### 交付前

- [ ] 代码、资源、日志和规格中的规则 ID 可互相追溯。
- [ ] 每个新缺陷都有修复前会失败的生产入口回归用例。
- [ ] 已实际运行的检查和未运行的检查分开记录。
- [ ] 已更新总计划状态；未完成原版对照的武器不标“已完成”。
