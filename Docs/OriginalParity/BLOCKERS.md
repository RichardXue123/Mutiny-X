# 阻塞项与人工操作

## 需要人工操作

### MANUAL-01 原版参考录像

需要在可运行的 Flash 原版中录制 Level 1 的完整流程：关卡进入、首回合镜头、悬停/选中、Throw Self、武器使用、敌方行动、空投、受击、落水和回合结束。静态 AS2 能确定状态和数值，但无法可靠证明所有嵌套 MovieClip 的最终合成外观、音频混音和主观镜头节奏。

所需输出：原始分辨率录屏，尽量保留鼠标位置和声音。此步骤不阻塞代码审计，只影响“视觉/听觉完美一致”的最终签收。

### MANUAL-02 Unity Player build 验收

待运行时资源路径修复后，需要从 Unity 执行 Windows Development Build，进入 Level 1 并验证关卡、角色、武器图、音乐和音效均出现。该操作将在 TODO 中保持 `[人工]`，直到你完成构建或允许自动化构建。

### MANUAL-03 退出当前 Play Mode 后重新导入

本轮编辑时 Unity 正在 Play Mode，且项目启用了不重载 Domain 的进入模式。新增脚本和大量原版帧已通过独立 C# 编译检查，但正在运行的场景仍是旧脚本域。需要停止 Play Mode，等待 Unity 完成导入/编译，再按 `VALIDATION.md` 重新进入 Level 1。

## 当前缺少的材料

### BLOCK-01 完整关卡集合

当前本地扫描基线只有 18 个关卡 XML，而反编译逻辑中能看到更多关卡/模式编号的痕迹。没有对应 XML 时，无法对缺失关卡的对象布局、初始库存和空投权重执行回归。

缺少：原版实际使用的其余关卡 XML，或能证明发行版本确实只包含这 18 关的资源索引。

### BLOCK-02 原版逐帧视觉基准

SWF、反编译脚本和导出帧可用，但某些嵌套 MovieClip 的遮罩、滤镜、运行时跳帧和父子时间轴同步不能仅凭扁平 PNG 目录自动证明最终画面。

缺少：可运行原版的逐帧录制，或带完整时间轴/矩阵/颜色变换的可靠导出清单。现有材料仍足以继续恢复大部分动画，只有最终像素级判定受阻。
